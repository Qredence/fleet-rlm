Standard Alembic migration layout under `migrations/` with a single-database configuration targeting Neon Postgres. `env.py` is the Alembic entry point: it prepends `src/` to `sys.path`, loads `.env` via python-dotenv, imports `fleet_rlm.persistence.models.Base` as `target_metadata`, and resolves the database URL from the `FLEET_DATABASE_URL` environment variable (falling back to `alembic.ini`). Async driver URLs (`postgresql+asyncpg://`, `sqlite+aiosqlite://`) are converted to synchronous drivers (`postgresql+psycopg://`, `sqlite://`) before connection. Migration scripts live in `versions/` and are generated from `script.py.mako`, which produces files with `upgrade()` / `downgrade()` functions using `alembic.op` and `sqlalchemy` constructs. The baseline migration `019f5b3c96bd_canonical_coordinated_turn_baseline.py` defines the full initial schema; subsequent migrations add columns and indexes incrementally.
