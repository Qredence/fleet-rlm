The repository is a single `pyproject.toml` project (`fleet-rlm`) whose `src/fleet_rlm` package exposes the FastAPI ASGI app (`fleet_rlm.main:app`) and two CLI entry points (`fleet`, `fleet-rlm`). Cross-cutting concerns are centralized at this level: `alembic.ini` drives schema migrations in `migrations/` against Postgres/SQLite; `openapi.yaml` is the single source of truth regenerated by `scripts/openapi_tools.py` and consumed by both the backend and the `tools/fleet-tui` Node.js client (separate pnpm project); `.env.example` plus TOML policy profiles select run environments (deno vs. daytona) and provider backends. The `Makefile` orchestrates the whole workspace — linting/formatting via ruff, type checking with `ty`, pytest runs with isolated env vars for deno/live/daytona markers, security scans (pip-audit + bandit), dependency checks (deptry), codebase-boundary enforcement (`check_codebase_tree`), and release artifact validation. Tests (`tests/`) span unit, contract, live integration, and e2e smoke tests against the same FastAPI app, while `scripts/` holds standalone utilities for DB init, snapshot management, benchmarks, and release hygiene. The TUI is a separate Node.js project invoked through `make tui-check` but shares its HTTP contract with the Python backend via the generated OpenAPI types.
