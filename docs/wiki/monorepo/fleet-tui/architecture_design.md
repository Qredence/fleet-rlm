The module is a Node.js ESM package (`package.json`, `type: module`) with a clear three-layer split:
- Entry & CLI layer (`src/cli.ts`, `src/cli-core.ts`): argument parsing, artifact download mode, session lifecycle, and the `run()` bootstrap that creates the `FleetApiClient`, resolves or resumes a session, projects durable turns via `projection.ts`, then hands control to the TUI.
- API & streaming layer (`src/fleet-api-client.ts`, `src/fleet-turn-stream.ts`, `src/sse.ts`): a typed HTTP client over generated OpenAPI types (`./generated/openapi.js`), an SSE parser (`sse.ts`) that validates chunk shapes against the `FleetUIMessageChunk` union, and a generator (`streamFleetTurn`) that enforces stream invariants (start → … → terminal → [DONE]) with one-network-retry on transient failures.
- TUI application layer (`src/tui/`): a state-driven architecture centered on `ConversationStore` (unidirectional event dispatch with a pure `reduce` function), a `RunController` that drives the SSE stream, a `FleetScreen` backed by `@earendil-works/pi-tui`'s `TUI`/`Editor`/`ProcessTerminal`, and a registry of slash commands (`commands.ts`) registered via `registerCommand`. Views live under `tui/views/` and are composed by `application.ts` which wires keybindings, autocomplete, theme, and the command presenter.

Dependency direction is strictly top-down: `cli.ts` → `application.ts` → (`store.ts`, `runner.ts`, `screen.ts`, `commands.ts`, `fleet-api-client.ts`). The store is renderer-independent and can be hydrated from durable turns via `projectDurableTurns` for session resume.
