The module is split into two logical layers. `models.py` defines the single SQLAlchemy `DeclarativeBase` (`Base`) plus all row classes (`UserRow`, `WorkspaceRow`, `SessionRow`, `TurnRow`, `RunRow`, `SandboxBindingRow`, `AttachmentRow`, `ArtifactRow`, `SkillRow`) with UUID primary keys, JSON columns, and declarative constraints/indexes. `database.py` exposes async engine/session factory creation, URL normalization (postgres→postgresql+asyncpg, sqlite→sqlite+aiosqlite), Alembic head compatibility checking, and a `create_tables` helper reserved for tests/dev. The `repositories/` subpackage implements concrete persistence adapters behind domain interfaces: `session_catalog.py` provides both `SqlAlchemySessionCatalog` and an `InMemorySessionCatalog`; `turns.py` provides `SqlAlchemyTurnStateStore` and `InMemoryTurnStateStore` implementing the full turn claim/settlement lifecycle; `artifacts.py` and `attachments.py` expose read/write catalogs backed by SQLAlchemy. Each repository class takes an `async_sessionmaker[AsyncSession]` via constructor injection, keeping them decoupled from engine construction. Dependency direction is one-way: repositories → models → database primitives; no cross-imports between sibling repository files except through shared models.
