The module is organized around a single execution entry point `RLMRunner.stream(context)` that consumes an immutable `RLMExecutionContext` (built from `PreparedCapabilities`, `RLMModelBundle`, `SessionContextManifest`, etc.) and yields a `TurnEventStream` of `RuntimeEvent`s. Internal layering:
- Contract/pin layer (`dspy_contract.py`, `dspy_interpreter_contract.py`) pins the exact DSPy 3.3.0b1 constructor and interpreter surface, exposing `build_native_rlm`, `bind_native_rlm_observer`, and `FinalOutput` helpers.
- Construction seam (`factory.py`, `lm_factory.py`) builds fresh `dspy.RLM` instances via `RLMFactory` and constructs `dspy.LM` bundles through either direct LiteLLM or Databricks AI Gateway tiers.
- Input boundary (`input_models.py`, `inputs.py`) defines frozen Pydantic DTOs and serializes host metadata into the `FleetRLMSignature` fields without leaking bodies.
- Execution core (`runner.py`) orchestrates: initial events → worker task (`_execute_rlm_in_worker` runs `rlm.acall` in a thread via `asyncio.to_thread`) → observation reconciliation between live `_DetailRelay` emissions and the normalized DSPy trajectory → final `PredictionResult` validation.
- Observability (`events.py`, `tool_observer.py`) defines a closed set of `RuntimeEventDetail` dataclasses and wraps each `dspy.Tool` through `observe_tool` to emit `ToolStarted/Completed/Failed` plus progress/integrity warnings.
- Safety (`sanitize.py`, `tool_guards.py`) redacts secrets from public text, validates declared outputs against sensitive patterns, and tracks workspace-file obligations and repeated-call stagnation.
- Context/data (`context.py`, `model_bundle.py`, `outcome.py`) hold frozen dataclasses for execution spec, model roles, and the settled `RLMOutcome`.
Dependency direction is strictly inward: runner depends on factory/dspy_contract/events/tool_observer; tool_observer depends on tool_guards and events; lm_factory depends only on config and dspy; no cross-imports back into higher layers.
