The module is organized into clear layers around immutable dataclasses in `models.py` (`SkillCard`, `SkillDefinition`, `SkillResource`, `SkillSelectionRef`, `ResolvedSkills`) that serve as the single source of truth for Skill metadata. `catalog.py` declares `_BUNDLED_SPECS` tuples and builds a frozen `SkillCatalog` keyed by deterministic UUIDs generated via `uuid5` with a fixed namespace; an `UnavailableSkillCatalog` subclass provides a test fixture. `resolver.py` implements pure exact-selection logic (`resolve_selected_skills`) that enforces max 4 selections, deduplication, and version pinning, returning a `ResolvedSkills` whose signature is either a per-Skill `dspy.Signature` or the default `FleetRLMSignature`. `signatures.py` defines the `DataAnalysisSignature` and a validator enforcing a fixed set of required input fields plus one canonical `answer` output. `tools.py` provides `SkillToolHost`, a turn-bound, RLock-guarded host exposing two DSPy tools (`load_skill`, `read_skill_resource`) that progressively reveal SKILL.md content and UTF-8 resources only after explicit loading, emitting structured events through `event_views()`. The `bundled/` package holds the actual skill assets (SKILL.md files, optional scripts/references) discovered at runtime via `importlib.resources.files`. Dependency direction is strictly inward: `tools` → `catalog` → `models`; `resolver` depends on `catalog`, `errors`, and `models`; `signatures` depends only on `dspy` and shared input models — no cross-imports between sibling modules except through these boundaries.
