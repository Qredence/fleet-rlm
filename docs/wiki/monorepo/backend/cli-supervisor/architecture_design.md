The module is organized as a thin CLI layer over the ASGI application in `fleet_rlm.main`. `__init__.py` re-exports two entry points (`fleet_main`, `fleet_rlm_main`) for the multi-command `fleet` CLI and the single-command `fleet-rlm` launcher. `main.py` builds an `argparse` hierarchy with subcommands `web`, `cli`, `deno`, and `doctor`; `_run` centralizes argument dispatch, invokes `require_safe_bind_host` from `bind_safety.py` to reject unauthenticated non-loopback binds, then either delegates to `supervisor.supervise()` (when `--tui` is implied) or runs uvicorn directly against `fleet_rlm.main:app`. `supervisor.py` is a self-contained process supervisor that validates prerequisites (pnpm, Node.js ≥22.19), checks port availability, starts the backend via `subprocess.Popen` with a new session, polls `/openapi.json` until ready, then launches the pi-tui TUI under `pnpm start`, and coordinates graceful shutdown by forwarding SIGINT/SIGTERM/SIGHUP and killing child process groups. `bind_safety.py` is a small pure-Python safety gate using `ipaddress.ip_address` to detect loopback hosts. Dependency direction is strictly inward: the CLI imports from `fleet_rlm.config`, `fleet_rlm.daytona.diagnostics`, and `fleet_rlm.persistence.database` only at call time to avoid circular imports.
