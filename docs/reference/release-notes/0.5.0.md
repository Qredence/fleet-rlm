# fleet-rlm v0.5.0 Release Notes

Release date: 2026-04-25

## Highlights

- Fleet-RLM is now a Daytona-only recursive workbench with one supported runtime substrate across the API, UI, CLI, docs, and release packaging.
- The backend agent core is smaller and more direct: a DSPy ReAct `FleetAgent`, tool discovery, persistent history, recursive RLM delegation, and isolated child sandboxes.
- The product shell now includes Workbench, History, Volumes, Optimization, and Settings with refreshed feature-owned frontend modules.
- The Optimization surface adds DSPy evaluation, GEPA runs, datasets, scoring, prompt snapshots, comparisons, and MLflow-backed quality workflows.
- The release workflow publishes verified distributions through TestPyPI smoke testing, PyPI trusted publishing, generated GitHub release notes, and deployment observability summaries.

## Breaking Changes

- Removed Modal as a supported runtime. Daytona is the only runtime substrate for execution, durable volumes, sandbox controls, and recursive work.
- Removed Fleet-RLM's optional FastMCP server surface. Use the HTTP/WebSocket API, CLI, and Daytona bridge callbacks instead.
- Removed the `fleet-rlm init` scaffold command and unused scaffold command references.
- Removed the dedicated `analyze_long_document` tool surface. Long-context workflows now route through variable-mode RLM execution and document ingestion paths.
- Replaced legacy Agent Framework / hosted-worker orchestration assumptions with the simplified DSPy ReAct runtime and FleetAgent session model.
- Retired frontend product routes remain unsupported: `taxonomy`, `skills`, `memory`, and `analytics` continue to fall through to `/404`.

## Added

- Added recursive `rlm_query`, batched RLM delegation, child sandbox isolation, bounded local workspace evidence staging, and durable DSPy history persistence.
- Added session history, session stats/restore/export, sandbox list/detail/delete/archive, run-step inspection, API-only memory listing, runtime diagnostics, and trace feedback APIs.
- Added Daytona filesystem/volume tools, snapshot management, LSP completions/symbols, hot resize, graceful stop/delete, archive, auto-stop refresh, resource sizing, and network firewall controls.
- Added host-side document fetching and redirect validation for bridged document ingestion.
- Added Optimization APIs and UI for datasets, runs, module metadata, GEPA execution, scoring, prompt snapshots, and run comparison.
- Added packaged release smoke checks that install the wheel, import `fleet_rlm`, serve `/health`, and confirm bundled UI assets render.

## Changed

- Reorganized backend ownership around `runtime/`, `integrations/daytona/`, `api/runtime_services/`, domain-specific database repositories, and focused schema modules.
- Reworked websocket lifecycle and workbench event handling around canonical stream kinds, richer trace rows, passive event subscriptions, HITL state, and explicit finalization.
- Reorganized frontend ownership into `features/{layout,workspace,volumes,settings,optimization,history}`, shared product components, and canonical AI Elements.
- Reworked Settings into a shared routed/overlay dialog and refreshed Workbench, Volumes, Optimization, and History shell behavior.
- Updated deployment docs for API-only cloud preflight checks and `FLEET_RLM_SERVE_UI=false`.
- Refreshed `AGENTS.md`, subsystem agent guides, architecture docs, API references, testing strategy, installation/deployment guides, and OpenAPI artifacts for the 0.5.0 contract.

## Fixed

- Hardened auth/session ownership checks for HTTP, websocket, sandbox, and memory access.
- Improved Daytona broker timeout handling, volume readiness, runtime diagnostics, workspace document loading, child interpreter labels, circular variable serialization, and session resume behavior.
- Fixed MLflow trace finalization, token usage tracking, automatic assessment gating, PostHog/MLflow config initialization, and trace lookup metadata.
- Fixed API/router issues around double auth enforcement, missing response models, 204 OpenAPI validation, blocking filesystem I/O in async handlers, runtime settings recovery, and release metadata drift.
- Fixed frontend regressions around workspace warning keys, reasoning auto-close, action-button locks, clarification answers, run-step tests, copy timers, routing/session hydration, and generated API sync.

## Removed

- Removed Modal setup docs, Modal-specific scaffold assets, stale hook files, legacy provider paths, old MCP server docs, and obsolete architecture/history snapshots.
- Removed dead API schema files, websocket helper shims, old runtime/tool modules, unreferenced frontend components, stale route shims, and unused dependency paths.
- Removed the old `src/fleet_rlm/integrations/providers/daytona/*` package in favor of `src/fleet_rlm/integrations/daytona/*`.

## Installation

```bash
uv tool install fleet-rlm==0.5.0
fleet web
```
